# 비공개 테스트 운영 가이드 (개인 개발자 계정)

## 요건 (2026-10-04 Play Console 고객센터 확인)

- 2023-11-13 이후 만든 **개인** 개발자 계정은 프로덕션(공개) 출시 전에 **비공개 테스트**를 해야 한다.
- 현재 기준: 테스터 **12명 이상**이 **14일 연속** 테스트에 참여(opt-in) 상태를 유지. 첨부 이미지의 ‘20명’은 2024년 12월 이전 기준이다.
- 이탈(탈퇴·그룹 나가기·계정 문제)에 대비해 **20명 이상** 모은다. 한 명이라도 중간에 빠지면 그 사람의 연속 일수는 처음부터 다시 센다.
- 14일이 지나면 Console 대시보드의 **프로덕션 액세스 신청**이 열린다. 신청 후 검토는 보통 7일 이내.
- 조직 계정에는 이 요건이 없다(D-U-N-S 번호 필요).

## 1. 준비 (D-3 ~ D-1)

1. 테스터 모집: 가족·지인·동호회·직장 동료 중 **Android 휴대폰 + Google 계정(Gmail)** 이 있는 사람. 자동 기록을 시험하려면 차량 Bluetooth(오디오 연결)가 있는 사람이 좋다. 아이폰 사용자는 참여할 수 없다.
2. 테스터 목록 방식 중 하나를 고른다.
   - **Google 그룹(권장)**: groups.google.com → 그룹 만들기 → 이름 예 `car-parking-testers` → ‘그룹 참여 가능 대상: 링크가 있는 모든 사용자’(또는 초대만). 테스터에게 그룹 주소를 보내 가입시킨다. Console에는 그룹 이메일 하나만 넣으면 되고, 사람을 추가·교체해도 Console을 고칠 필요가 없다.
   - **이메일 목록**: Console → 테스트 → 비공개 테스트 → 테스터 → 이메일 목록 만들기 → 테스터 Google 계정 이메일을 쉼표로 입력. Play에 로그인한 계정과 같은 이메일이어야 한다.
3. 테스터 개인 이메일 목록은 저장소에 커밋하지 않는다(공개 저장소).

## 2. 트랙 만들기와 업로드 (D0)

1. Console → 테스트 및 출시 → 테스트 → **비공개 테스트** → 트랙(기본 ‘Alpha’) 관리.
2. 국가/지역: **대한민국**.
3. 테스터: 위의 Google 그룹 이메일 또는 이메일 목록 선택. **피드백 URL 또는 이메일**: `dydy7270@naver.com`.
4. 새 버전 만들기 → `android/app/build/outputs/bundle/playRelease/app-play-release.aab` 업로드(서명된 0.3.12, versionCode 15 이상). 출시 노트(한국어) 작성 → 검토 → 출시.
5. 처음 올린 버전은 검토를 거친다(몇 시간~며칠). 검토가 끝나야 테스터가 설치할 수 있다.
6. 테스터 탭의 **참여 링크(opt-in URL)** 를 복사한다. 형식: `https://play.google.com/apps/testing/app.car.parking`

1) (Google 그룹을 쓰는 경우) 이 그룹에 먼저 가입해 주세요: <그룹 주소>
2) 휴대폰의 Play 스토어와 같은 Google 계정으로 아래 링크를 열고 '테스터 되기'를 눌러 주세요.

## 4. 테스트 기간 운영 (D1 ~ D14)

| 시점 | 할 일 |
|---|---|
| D1 | Console → 테스터 수·설치 수 확인. 12명 미만이면 추가 모집 |
| D3 | 첫 피드백 요청(아래 질문). 문제 수정 |
| D5~D8 | 피드백 반영한 업데이트 1회 이상 배포(versionCode 증가). 프로덕션 신청서에서 ‘테스트 후 바꾼 점’의 근거가 된다 |
| D10 | 참여 유지 안내(앱 삭제·탈퇴 금지) 한 번 더 |
| D14+ | 12명 이상이 14일 연속 참여했는지 확인 후 프로덕션 액세스 신청 |

테스트 기간에 확인할 기록을 남긴다(아래 ‘테스트 기록표’). 신청서 답변은 실제 기록을 근거로 쓴다.

### 테스터에게 물어볼 것

1. 휴대폰 기종 / Android 버전
2. 차량 등록: 설정 → 차량 관리에서 내 차가 목록에 보였나요?
3. 자동 표시: 시동을 끄고 내렸을 때 층수 화면이 자동으로 떴나요? (화면 켜짐 / 꺼짐 / 잠금 상태 각각) 몇 초 걸렸나요?
4. 잠깐 시동을 껐다 켰을 때(2초 안 재연결) 화면이 뜨지 않았나요?
5. 층수 릴로 고르기·저장이 쉬웠나요? 사이드바 영상·애니메이션이 자연스러웠나요?
6. 상태바·잠금 화면 층수 표시, 홈 화면 위젯이 제대로 보였나요?
7. 주차 사진 찍기 → 크게 보기 → 다시 찍기 / 삭제가 잘 됐나요?
8. 지도에 주차 위치(P)와 현재 위치가 맞게 보였나요?
9. 배터리 사용량이 눈에 띄게 늘었나요? 제조사 절전 설정 때문에 자동 표시가 안 된 적이 있나요?
10. 헷갈렸던 화면이나 문구

## 5. 프로덕션 액세스 신청 답변 초안

Console 대시보드 → ‘프로덕션 액세스 신청’. 질문은 세 부분이다. **[ ] 안은 실제 테스트 결과로 채운다. 실제로 하지 않은 일을 쓰지 않는다.**

**비공개 테스트 정보**

- 테스터 모집이 얼마나 쉬웠나요? → `가족·지인·동호회에서 [ ]명을 모았습니다. Google 그룹으로 참여 링크를 공유했고, 차량 Bluetooth가 있는 Android 사용자를 우선 모았습니다.`
- 테스터 참여도(모든 기능을 사용했는지, 실제 사용과 비슷했는지) → `테스터들이 [ ]일 동안 실제 주차할 때 사용했습니다. 자동 표시, 층수 저장, 상태바·위젯, 사진, 지도 기능을 [ ]명이 사용했습니다.`
- 받은 피드백 요약 → `[예: 일부 기종에서 절전 설정 때문에 자동 표시가 늦음, 릴 글자 크기 의견 등]`

**앱 정보**

- 대상 사용자 → `지하·다층 주차장을 자주 이용하는 운전자(18세 이상)`
- 앱의 가치·차별점 → `등록한 차량의 Bluetooth 연결이 끊기는 순간 앱이 바로 열려 층수를 한 번에 기록합니다. 계정 없이 모든 기록을 휴대폰에만 저장하고, 상태바·위젯에서 앱을 열지 않고도 층수를 확인합니다.`
- 첫해 예상 설치 수 → 현실적인 범위 선택(예: 0~1만)

**프로덕션 준비 상태**

- 테스트 결과로 바꾼 점 → `[버전 ]에서 [ ]를 고쳤습니다.` (실제 변경 내역, `docs/releases/` 참고)
- 출시 준비가 됐다고 판단한 근거 → `[ ]개 기종에서 자동 표시·저장·상태바 표시를 확인했고, 마지막 [ ]일 동안 새 오류 보고가 없었습니다. 실기기 확인 결과는 VERIFICATION.md에 기록했습니다.`

## 6. 프로덕션 출시 (승인 후)

1. 프로덕션 → 새 버전 → 테스트한 AAB 승격(또는 같은 AAB 업로드) → 국가: 대한민국 → 출시 노트.
2. 검토 기간은 보통 수일, 처음에는 7일 이상 걸릴 수 있다.
3. 비공개 테스트 트랙은 그대로 두고 이후 업데이트를 먼저 테스터에게 배포하는 데 쓴다.
