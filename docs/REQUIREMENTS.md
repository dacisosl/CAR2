# 요구사항

MUST는 MVP 완료 조건이다. DEFAULT는 사용자가 별도 지정하지 않은 구현 기본값이다.

| ID | 수준 | 요구사항 |
|---|---|---|
| R01 | MUST | Android 앱으로 제작 |
| R02 | MUST | 간결한 로고·차량 아이콘, 클래식(화이트·블랙·회색)과 스틸 포인트(블랙·화이트 + 실버 디테일) UI |
| R03 | MUST | 홈: 상단 설정/BT, 경과 시간, 층수·차량, 위치명, 넓은 지도 |
| R04 | MUST | 홈 ‘내 차 위치 보기’, ‘기록 수정’, BT 상태 텍스트 줄 제거 |
| R05 | MUST | Bluetooth 아이콘을 설정 옆에 두고 준비 상태를 명암/채움으로 표현 |
| R06 | MUST | 등록 차량의 연결 해제에만 반응하고 짧은 재연결 확인 |
| R07 | MUST | 사전 설정을 마친 지원 기기에서 **알림 탭 없이 앱 화면 자동 표시** |
| R08 | MUST | 정상 백그라운드와 화면 꺼짐·잠금 상태의 자동 표시 실기기 확인 |
| R09 | MUST | 저장한 위치의 왼쪽/오른쪽 사이드바를 자동으로 열기 |
| R10 | MUST | 세로 릴 스크롤 층수 선택과 중앙 스냅 |
| R11 | MUST | 손잡이 길게 누르기·드래그로 패널 좌우 이동, 위치 영속 저장 |
| R12 | MUST | 패널 내부의 카메라 아이콘-only 버튼 + 작은 저장 버튼, 2열·1행 |
| R13 | MUST | 기압·기준점 정보를 이용한 층수 추천, 기준 부족/센서 없음 시 수동 선택 |
| R14 | MUST | 사용자 확인·저장 전 기존 확정 기록을 덮어쓰지 않음 |
| R15 | MUST | 차량 선택·권한 안내·자동 표시 테스트를 따라 하기 쉽게 구성 |
| R16 | MUST | 실제 지도 SDK의 밝은 커스텀 스타일로 새 참조 반영, 저장 P 핀·현재 위치·재중앙, 실제 정확도와 오래된 위치 구분 |
| R17 | MUST | 사진 선택·기록 저장, 앱 재실행 후 확정 기록 복원 |
| R18 | MUST | 중복 연결 해제·재연결·권한 거부·센서 없음·위치 없음 상태 처리 |
| R19 | DEFAULT | 계정 없이 로컬 우선 저장, Kotlin·Compose·Room·DataStore |
| R20 | DEFAULT | CAR 가칭, 네이버 Android SDK 커스텀 스타일을 국내 지도 1차 구현 방향으로 사용 |
| R21 | MUST | 설정의 미리보기 카드에서 클래식·스틸 포인트 테마 선택, 즉시 전체 화면 적용, 앱 재실행·자동 진입에도 유지 |

## 필수 자동 표시 흐름

등록 차량 연결 → 연결 해제 감지 → 짧은 재연결 확인 → 주차 후보 생성 → 앱 자동 표시 → 마지막 위치의 사이드바 열기 → 층수 추천/수동 선택 → 확인·저장.

추천 계산이 늦으면 패널을 먼저 열고 결과를 갱신한다. 사용자가 이미 릴을 움직였으면 늦게 도착한 추천으로 사용자의 선택을 덮어쓰지 않는다.

## 지원 조건

자동 표시가 핵심이며 ‘알림을 누르면 열리는 앱’으로 요구사항을 축소하지 않는다. 다만 시스템 설정에서 앱을 강제 중지한 상태, 권한이 없는 상태, OEM 정책으로 감지가 중단된 상태를 정상 동작처럼 보고하지 않는다. 초기 기술 단계에서 OS·제조사별 지원 조건을 정하고 자동 표시 성공 여부를 기록한다. 기본 화면 실행 권한과 백그라운드 감지 서비스 실행 조건은 각각 검증한다.

잠금 화면 위에 앱을 표시할 수 있게 구현하되 보안 잠금 해제를 자동으로 우회하지 않는다. 카메라 촬영·외부 사진 선택 같이 인증이 필요한 동작은 정상 시스템 인증 흐름을 따른다.

## 범위

포함: 현재 주차 기록, 자동 감지·화면 표시, 층수 추천, 수동 보정, 사진, 기본 지도, 초기 설정, 두 가지 디자인 테마 선택.

첫 버전의 추가 범위로 확정하지 않은 것: 계정, 서버 동기화, 결제, 광고, 예약·주차요금 계산, 도보 경로·예상 시간, 실내 길찾기·주차장 실내 도면, 모든 건물의 자동 층수 데이터, iOS 앱.
